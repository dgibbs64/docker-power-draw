# docker-power-draw

Containerised CPU, memory, and GPU power draw workload with optional BOINC attachment.

This image runs up to four types of load simultaneously:

- BOINC client (optional project or account-manager attachment)
- CPU load via `stress-ng` (all cores)
- Memory load via `stress-ng` (80% RAM)
- GPU hardware-accelerated video transcode loop via `ffmpeg` (when supported hardware is available)

## What It Does

At startup, the container:

1. Starts the BOINC client.
2. Optionally attaches BOINC using environment variables.
3. Starts CPU load across all cores with `stress-ng`.
4. Starts memory load using 80% of available RAM with `stress-ng`.
5. Detects GPU type and encoder support, then starts a hardware-accelerated `ffmpeg` transcode loop when possible.
6. Prints a load summary (BOINC / CPU / Memory / GPU status).

If no supported GPU path is available, the GPU load is skipped and CPU and memory load still run.

## Build

```bash
docker build -t docker-power-draw .
```

## Run

Minimal run (CPU and memory load only):

```bash
docker run --rm --name power-draw docker-power-draw
```

With Intel or AMD GPU (VAAPI/QSV):

```bash
docker run --rm --name power-draw --device /dev/dri docker-power-draw
```

With NVIDIA GPU (requires `nvidia-container-toolkit` on the host):

```bash
docker run --rm --name power-draw --gpus all docker-power-draw
```

With BOINC project attachment:

```bash
docker run --rm --name power-draw \
  --device /dev/dri \
  -e BOINC_PROJECT_URL=https://www.worldcommunitygrid.org \
  -e BOINC_ACCOUNT_KEY=YOUR_KEY \
  docker-power-draw
```

## Docker Compose

A `docker-compose.yml` is included. By default it passes `/dev/dri` for Intel/AMD hosts.
For NVIDIA hosts, remove the `devices` block and uncomment the `deploy` section in the file.

```bash
docker compose up -d
```

## Environment Variables

BOINC attachment precedence (first match wins):

1. `BOINC_PROJECT_URL` + `BOINC_ACCOUNT_KEY` attach to a single specific project
2. `BOINC_ACCT_MGR_EMAIL` + `BOINC_ACCT_MGR_PASSWORD` attach via an account manager. The manager URL is set by `BOINC_ACCT_MGR_URL` (default `https://bam.boincstats.com`). The legacy `BOINC_BAM_EMAIL` / `BOINC_BAM_PASSWORD` names still work as the credentials.
3. `BOINC_DEFAULT_KEY` attach to World Community Grid
4. If none are set, BOINC idles

Account manager URLs for `BOINC_ACCT_MGR_URL`:

- BAM! (BOINCstats): `https://bam.boincstats.com` (default)
- Science United: `https://scienceunited.org`
- GridRepublic: `https://www.gridrepublic.org`

With Science United, you choose science areas on the website and it assigns projects for you automatically.

GPU video source:

- `VIDEO_URL` (optional) — download a video file to use as the encode source instead of the default synthetic source

## GPU Behaviour

The script attempts GPU load in this order:

1. Intel iGPU — Quick Sync (`h264_qsv`, preset `veryslow`, 40 Mbps), falling back to VAAPI if QSV is unavailable at runtime
2. NVIDIA — NVENC (`h264_nvenc`, preset `p7`, 40 Mbps); detected via `lspci`, `/dev/nvidia*` device nodes, or `nvidia-smi`
3. AMD — VAAPI (`h264_vaapi`, 40 Mbps)
4. Generic VAAPI fallback when `/dev/dri` is present but the vendor is not identified

If no supported GPU path is available, the GPU load is skipped silently.

The default video source is a synthetic 1080p60 stream generated by `ffmpeg`'s `lavfi` filter — no download required, no disk I/O, and consistent load regardless of network availability. Set `VIDEO_URL` to use a real file instead.

## NVIDIA Setup

`nvidia-container-toolkit` must be installed on the host. Installation instructions are available in the [NVIDIA Container Toolkit documentation](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/install-guide.html).

Once installed, pass `--gpus all` (CLI) or uncomment the `deploy` block in `docker-compose.yml`.

## Shutdown Behaviour

`Ctrl+C` (SIGINT) and SIGTERM are trapped for a graceful exit:

- Stops all background `ffmpeg` and `stress-ng` processes
- Sends `boinccmd --quit`
- Waits for child processes and exits cleanly

## Exposed Port

- `31416` (BOINC RPC, optional)

The container exposes this port in the image metadata, but you only need to publish it with `-p` if you want host access to the BOINC RPC interface.
